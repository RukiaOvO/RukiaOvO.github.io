# Vercel 新主页：产品定义与实施基线

更新：2026-11-02。依据用户最新澄清：原站功能应改良或优化，不要求全部保留，不需要在原站基础上重构。用户已授权自主决定方案和外部资料选择。

## 1. 目标与边界

独立设计并开发一个部署在 Vercel 的新个人主页。旧站提供使用场景、个人信息和真实内容参考，不作为必须兼容的产品规格或代码架构。

- 新站的信息结构、视觉、交互、数据接口和发布方式按新需求设计。
- 功能可以改良、合并、替换或分期；不以旧功能数量相等作为完成标准。
- 不修改 Hugo 模板、主题、旧前端脚本来充当新站实现。
- 已搭建的 Next.js 工程属于新站基础，可复用；现有文章、图片和公开个人资料可作为初始内容。
- 原文章路径能低成本延续时继续沿用，但不为全面旧接口、旧计数或旧 CMS 兼容阻塞新站。
- Vercel 真实部署是交付条件；本地可运行、来源链接或长期占位不能冒充已实现的功能。

本文件取代旧计划中“保留全部能力”“先获得全部 Worker 契约”“完整兼容后才能发布”等强制前提。旧盘点仍可用于参考，不再是新产品的逐项验收表。

## 2. 产品方向

**2026-11-02 最新补充：用户要求风格和布局接近旧主页，方便原有场景合理排布。当前采用 GitHub Profile 仪表盘式的蓝灰配色、半透明卡片、左侧个人资料和右侧功能区，取代上一轮的大标题杂志式布局。在线写作与 ClouDNS 接入说明见 [layout-publishing-domain.md](layout-publishing-domain.md)。**

定位：以个人介绍、研究与工程成果、文章阅读为核心的个人站点，动态和生活状态为辅助。首页不默认堆叠所有数据面板。

默认导航：首页、文章、项目、动态、关于。首页展示简洁身份介绍、精选成果、近期文章和少量近期动态；完整列表进入对应页面。

| 原有场景 | 新站的改良方向 | 首版决策 |
| --- | --- | --- |
| 个人资料、技能、时间线、社交链接 | 形成清晰的身份与研究介绍；简化重复标签，把较长经历放到关于区域 | 核心范围 |
| 文章与论文研读 | 优化摘要、分类发现、组合筛选、目录与阅读体验；搜索与筛选状态一致 | 核心范围 |
| GitHub 热力图与公开事件 | 优先呈现项目成果、真实开发活动与时间；热力图按信息价值决定位置，不占据首屏主体 | 核心范围：项目与近期开发活动 |
| RSS 聚合 | 独立动态页中呈现关注来源；有来源筛选、去重、更新时间、部分源失败状态 | 首版扩展，完成后才加入正式导航内容 |
| 天气、Steam、最近游玩 | 可合并成较轻的近况区域，按需加载；避免多个实时组件影响阅读主线 | 次级范围，独立评估后接入，不要求机械复刻 |
| 访客累计计数 | 优先解决实际访问分析需求，避免不准确的装饰性累计数字 | 首版不依赖旧计数迁移；后续按需要评估 Vercel 分析能力及配额 |
| 评论与留言 | 在文章或留言区域按需加载；减少首屏第三方请求 | 优先复用 Giscus，实际可用后验收；旧讨论关联是加分的连续性需求 |
| 内容管理 | 保持 Markdown/Git 的简单发布机制，建立提交到 Vercel 的可验证发布链路 | 核心范围是发布能力，不强制绑定旧 Worker OAuth；网页 CMS 独立评估 |
| 昼夜主题与响应式布局 | 保留手动浅/深切换，自动模式规则明确；优先可访问性、移动阅读及加载稳定性 | 核心范围 |

以上是本次自主决定的首版范围，不是对用户每一个细节的逐字要求。实际实施中按价值调整并记录，不把未经实现的功能标记完成。

## 3. 技术与外部资源决策

- Next.js App Router + TypeScript + Tailwind，部署至 Vercel。旧 Hugo 构建只服务旧站。
- 新站使用自己的配置与模块边界，不要求复制旧 YAML/Worker 的内部结构。文章内容可以复用，内容与界面实现分离。
- GitHub 项目和活动优先使用公开 API；RSS 使用允许的来源列表及服务端解析；天气如纳入则使用 Open-Meteo。
- 新服务各自定义响应格式、超时、缓存、错误与数据更新时间。不为了兼容而先重建全部旧接口。
- 旧 Worker 可作为有价值且可验证的可选数据源，但源码和累计存储不再是所有开发工作的前置条件。
- 部署域名先使用 Vercel 分配的稳定域名。只有实际获得域名后才记录最终地址；不虚构某个 `vercel.app` 域名已归属本项目。
- canonical 优先取显式 `SITE_URL`，否则使用 Vercel 的生产域名环境变量；本地默认 localhost。`github.io` 旧地址继续由 GitHub Pages 管理。
- 公开项目展示只使用真实仓库资料。已查到 `RukiaOvO/Kg4se`（软件工程课程的多模态知识图谱增量构建平台）及个人站点仓库，可用于初始项目内容，不虚构经历或成果。

## 4. 实施顺序

1. **产品与页面设计**：围绕介绍、成果、阅读确定首页层次和项目/关于页面内容；以本文件替换兼容迁移主线。
2. **新站基础完善**：修复筛选回显、目录锚点等已经发现的缺陷；清晰隔离新站配置和旧站代码，完善文章阅读和主题体验。
3. **成果与动态实现**：先接公开 GitHub 数据与项目展示，再实现 RSS 等被纳入本轮范围的功能。每项有真实成功路径及失败降级，不交付空壳导航。
4. **发布与外部服务**：建立 Markdown 提交→检查→Vercel Preview 的流程；按需接入评论或 CMS，不为兼容旧 OAuth 增加不必要依赖。
5. **真实部署与体验验收**：完成 Vercel Preview、生产部署、移动/桌面阅读、键盘操作、内容正确性、SEO 和实际接口测试；保存真实部署地址和构建记录。
6. **后续增强**：根据新站实际使用价值加入近况、天气、游戏或访问分析；无需为复刻旧站而全部先做。

## 5. 当前事实与阻塞

2026-11-02 已完成首页重新设计、独立项目/关于页面、新站配置、GitHub/RSS 服务端数据和动态交互。最新实现与验证见 [new-site-delivery.md](new-site-delivery.md)。以下早期基础情况仅作为过程记录。

- 已有新 Next.js 基础工程、静态首页、文章列表/详情、主题及本地测试。它们可复用，但当前布局并不因此自动成为最终设计。
- 已修正旧标签大小写/空白导致筛选控件不回显的问题，并为 Markdown 标题加入安全 id 前缀、同步文内锚点；这些是新工程质量修复，不构成旧站重构。
- 已读取 GitHub 公开仓库信息和 Open-Meteo 真实响应。
- 本地探测旧 Worker 的 GitHub/RSS/Steam 接口连接超时；没有调用可能增加计数的 visitor 接口。
- 未发现现成的 Vercel/Cloudflare CLI 登录配置或对应环境令牌；computer-use 浏览器检查因本地服务不可用失败，不能据此判断浏览器账号是否已登录。
- 已完成 Vercel 匿名临时部署；有效期和线上结果见交付记录。长期项目归属与 Git 发布仍需用户登录账号。用户授权可以决定资源和方案，但不能凭空获得账号会话。

## 6. 首版完成定义

新主页在 Vercel 上实际可访问；身份与项目资料真实；文章可发现、可阅读、可持续发布；本轮选择的动态和评论功能确实可用；错误不阻塞核心内容；移动端和键盘操作正常；SEO 与实际域名一致。

原站所有功能逐项复刻、旧 Worker 重构、访客累计迁移、Decap OAuth 原样兼容不属于默认完成条件。若后续重新纳入某项，则为其单独定义价值、实现方式和验收标准。
